# План реализации

План рассчитан на 5 рабочих дней из задания. Этапы последовательны: каждый заканчивается проверяемым результатом. Реализация приложения начнётся отдельным шагом после подготовки этого проекта.

## День 1 — каркас и контракт

- Создать клиент React + TypeScript + Vite и небольшой Node.js сервер в одном репозитории.
- Описать типы сессии, чата, сообщения и уведомления; подготовить fixtures ответов GREEN-API.
- Сделать маршруты сервера и тестовый адаптер API, не требующий реальных учётных данных.
- Добавить команды `dev`, `build`, `test`, `lint`, пример конфигурации и README запуска.
- Готово, когда клиент и сервер поднимаются локально, а сборка/типизация проходят.

## День 2 — подключение и создание чата

- Сделать форму `apiUrl`, `idInstance`, `apiTokenInstance`, валидацию и краткоживущую серверную сессию.
- Проверить доступность/состояние инстанса и показать безопасные ошибки.
- Реализовать ввод номера, `CheckAccount`, привязку канонического `chatId` и список чатов.
- Покрыть контрактными тестами неверные данные, недоступный инстанс, ненайденный номер и лимит метода.
- Готово, когда новый чат создаётся через подставной API и клиент показывает все основные состояния.

## День 3 — отправка и получение

- Реализовать `SendMessage` с ограничением 4000 символов, состоянием отправки и защитой от повторов.
- Сделать один последовательный цикл `ReceiveNotification`/`DeleteNotification`, фильтрацию текста, сопоставление `chatId`, дедупликацию и задержки при ошибках.
- Добавить доставку обновлений клиенту и автоматические сценарии «отправил → пришёл ответ», повторного уведомления и сбоя до подтверждения.
- Готово, когда полный диалог работает с подставным GREEN-API без дублей.

## День 4 — интерфейс и устойчивость

- Оформить простой интерфейс по мотивам MAX: список чатов, переписка, поле ввода, мобильная компоновка.
- Доработать пустые состояния, доступность, ошибки сети, отключение сессии и очистку чувствительных данных.
- Проверить узкий/широкий экран и основные сценарии в выделенном headless-браузере.
- Готово, когда основной сценарий понятен без чтения документации и UI не ломается при сбоях.

## День 5 — финальная проверка и передача

- Запустить полный автоматический набор: типизация, линтер, unit, контрактные и UI-тесты, production-сборка.
- Проверить отсутствие токенов и личных данных в репозитории, логах и собранном клиенте.
- Дописать README с локальным запуском, архитектурой, ограничениями и ссылками на первичные документы.
- По возможности разместить клиент с постоянно работающим сервером и добавить ссылку; подготовить скриншоты.
- Готово, когда GitHub-репозиторий содержит рабочий код, инструкцию и проверяемые результаты автоматических тестов.

## Порядок при нехватке времени

1. Сквозной сценарий: подключение → чат → отправка → ответ.
2. Корректная очередь уведомлений, ошибки и защита токена.
3. Адаптивный аккуратный UI и инструкция запуска.
4. Публичная демонстрационная ссылка и дополнительные косметические детали.

Не расширять обязательный объём медиа, группами или действиями над сообщениями до завершения пунктов 1–3.
