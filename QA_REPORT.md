# Проверка тестового задания

Дата: 29 сентября 2026 года. Проверенная версия: `9007912` (`main`).

## Результат по требованиям

| Требование | Результат | Проверка |
| --- | --- | --- |
| React-интерфейс | Подтверждено | Сборка, открытие опубликованной страницы, отсутствие ошибок JavaScript. |
| Подключение инстанса GREEN-API | Подтверждено с подставным API; реальный инстанс не проверен | Сквозной сценарий с production-сервером; опубликованный сайт возвращает понятную ошибку для неверного адреса и токена. |
| Создание чата по номеру | Подтверждено с подставным API | Номер нормализуется, `CheckAccount` возвращает канонический `chatId`, чат открывается в интерфейсе. |
| Отправка текста | Подтверждено с подставным API | Проверены запрос `SendMessage`, отображение исходящего сообщения и его состояние «в очереди». |
| Получение ответа | Подтверждено с подставным API | Уведомление появляется в нужном чате без перезагрузки, подтверждается через `DeleteNotification`, повтор не создаёт дубль. |
| Адаптивный интерфейс | Подтверждено | Headless Edge на ширинах 1440 и 390 px; на мобильной ширине нет горизонтального переполнения. |
| Репозиторий, инструкция и публичная ссылка | Подтверждено | GitHub, README, Render Free, HTTP 200 для страницы и `/api/health`. |

## Запуски

- `npm run check`: типы, линтер, 12 unit/контрактных тестов, сборка и production smoke прошли.
- `npm run test:e2e`: 3 браузерных сценария прошли в отдельном headless Edge с аппаратным WebGL.
- Сквозной сценарий на production-сервере с подставным GREEN-API: подключение → создание чата → отправка → входящее уведомление → подтверждение → отключение; ошибок JavaScript нет.
- Публичный адрес `https://max-chat-react-test-assignment.onrender.com/`: страница и `/api/health` отвечают HTTP 200. Без сессии создание чата возвращает 401; неверный адрес API — 400; неверный токен — 401. Сообщения об ошибках отображаются в интерфейсе.

## Граница проверки

Живой обмен сообщениями между MAX аккаунтами не подтверждён. Для него нужен авторизованный в MAX инстанс GREEN-API, настроенная очередь HTTP-уведомлений и второй MAX аккаунт для ответа. Регистрация требует подтверждения почты, а авторизация инстанса — QR-кода из MAX на телефоне. Эти данные не использовались и в репозиторий не добавлялись. Следовательно, соответствие формату API подтверждено по документации и подставным ответам; доставку через реальный сервис утверждать нельзя.

На Render Free процесс засыпает после простоя. Чаты и сессии хранятся в памяти и сбрасываются при перезапуске; после этого требуется повторное подключение. Это ограничение демоверсии, а не проверенная возможность постоянного хранения переписки.
